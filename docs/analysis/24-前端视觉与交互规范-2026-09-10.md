# 24 · 前端视觉与交互规范

> 供 DeepSeek 实施。与 [23 号方案](23-文字生涯实施方案-2026-09-10.md) 一起使用。以下设计 token、尺寸、布局和文案为本项目原创设计决策，不是从参考网站精确提取的 CSS。

## 1. 参考网站与核验边界

本次访问了用户指定的 [Sondaven](https://sondaven.com/en) 和 [HLTV](https://www.hltv.org/)，成功读取页面内容。内置浏览器已创建两个标签，但读取页面画面/可访问性状态连续超时；备用 Chrome provider 不可用。没有完成实时桌面/移动端截图核验，不能声称做过像素取样、动效实测或像素级复刻。

补充依据：Sondaven 创作者的 [项目说明](https://me.muz.li/chopei_iv/son-daven) 明确描述了以演变场景、滚动交互和声音构建叙事体验。HLTV 的 [官方设计说明（2017）](https://www.hltv.org/news/20530/a-new-beginning-for-hltvorg) 解释了保留熟悉信息布局、上下文导航和夜间模式的设计；它是历史设计依据，不等于当前页面截图。当前 HLTV 首页可读取赛事、新闻、排名与转会模块。

由此制定的方向：**电竞职业纪录片 + 可阅读的个人故事 + 专业赛事资料页**。

| 参考 | 提取原则 | 在本项目里的落点 |
|---|---|---|
| Sondaven | 用场景与叙事顺序建立情境；控制阅读节奏 | 新建生涯/章节切换的短序章；具有地点、人物与氛围的场景阅读区 |
| HLTV | 清楚的赛事、新闻、排名分区与上下文导航 | 世界页与比赛页使用紧凑的标题、结果行、数据表、日期分组 |
| 本项目设计 | 同一个人置身于真实运行的竞技世界 | 首页优先“我此刻的处境和选择”，数据在辅助区解释情境 |

实施者能访问参考站时，先观察 1440 与 390 视口，再记录差异；不能因访问失败停止全部实现，按本规范完成原创设计。禁止下载两站的品牌标识、酒店/选手照片当自有素材，也不要复制布局到逐像素、照抄页面文案。公开页面是设计参考，不是游戏运行时依赖。

## 2. 视觉系统

### 2.1 固定基调

全局使用深墨蓝框架、暖纸色阅读面、低饱和金色强调。章节/比赛强调深色；长篇对白使用暖浅底与深字。资料页维持深色表格，通过细分隔线与排版组织信息。

```css
:root {
  --bg: #111820;
  --surface: #19232e;
  --surface-raised: #22313e;
  --line: #354553;
  --text: #edf0f2;
  --muted: #a8b6c2;
  --paper: #eee8da;
  --paper-text: #202720;
  --paper-muted: #555e52;
  --accent: #d3b886;
  --accent-ink: #17212a;
  --link: #8cc8eb;
  --positive: #8cc6ac;
  --negative: #ed9e98;
  --focus: #a9d9fb;
  --radius-sm: 4px;
  --radius-md: 8px;
}
```

这些颜色需要在实际字号和背景上检查对比度：正文至少 4.5:1，大字/必要 UI 边界至少 3:1。金色按钮用深字；暖纸背景链接/状态文字使用足够深的变体，不能照搬浅蓝/浅绿。错误同时给图标或文字，不能只变红。

字体：界面与正文用 `"Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`；章节标题可用 `"Noto Serif SC", "Songti SC", serif`；比分与数字用 tabular-nums。字体本地/合法加载并有 fallback，首屏不等外网字体下载。

| 用途 | 桌面 | 手机 | 规则 |
|---|---|---|---|
| 章节序章标题 | clamp(40px, 5vw, 80px) | 36–44px | 不超过 2–3 行；不强制全英文 |
| 场景标题 | 32–40px | 28px | 6–16 个汉字为佳，允许换行 |
| 故事正文 | 18px / 1.85 | 17px / 1.85 | 阅读列最大 38–42em；可调字号 |
| 普通 UI | 15px / 1.5 | 15px / 1.5 | 重要标签不得压到 11px |
| 资料表格 | 14px / 1.5 | 14px / 1.5 | 数字右对齐、队名左对齐 |
| 日期/次要标签 | 12–13px | 12–13px | 高对比、避免整段大写英文 |

间距只用 4/8/12/16/24/32/48/64px 这组值。按钮高 44–48px，选择行高度由内容决定，最少 64px。主要区域最多两层表面，不在大卡片里继续套三层小卡片。常态无明显阴影；弹层可以有一层轻阴影。

### 2.2 装饰边界

- 装饰围绕竞技场语境：场馆走廊、训练桌、战术板、机位轮廓、纸质赛程、编号与细分隔线；没有图片时用原创 CSS/SVG 线稿与色块，保持完整构图。
- 图像只在章节序章和重要赛事视觉区出现，不能给每条训练/财务信息配巨图。
- 不使用紫蓝渐变、霓虹发光、玻璃拟态、满屏胶囊标签、随机 emoji、彩虹属性条、四处漂浮粒子、伪 3D 大奖杯。
- 不做酒店式长滚动营销首页，不写“开启你的传奇之旅”占据一整屏。首次章节引子可以有留白，但主按钮与剧情入口须清楚。
- 不复用历史已删除素材路径；缺队标时显示由队名生成的中性字母/汉字徽记，不显示断图。

## 3. 页面信息架构（6 个主页面）

主导航：**生涯 / 赛程 / 战队 / 世界 / 档案 / 设置**。训练、资金、转会放在对应上下文中，不各自变成一级空页面。

| 页面 | 主内容 | 次内容 | 数据来源 |
|---|---|---|---|
| 生涯 | 当前场景、对话/选择、结果、下一步 | 身份摘要、下一场、未兑现承诺 | 新 CareerView + `/view` |
| 赛程 | 按日期的正式赛事与状态；单赛事/单场细节 | 赛前准备、赛后叙事、正式比分 | `/calendar`、`/events/{name}`、`/replay`，请求参数按实际协议 |
| 战队 | 阵容与主角关系、当前合同/角色 | 训练安排、正式转会候选 | `/view`、training/transfers API，缺投影先补后端 |
| 世界 | 电竞新闻主列、排名、转会 | 按赛事/队伍查看事实 | journal world_wire、`/world`、`/top20`；未暴露字段走后端投影 |
| 档案 | 已经历的场景与决定、赛季、荣誉 | 生涯结局、历史比赛 | career/history、`/archive`、`/ending` |
| 设置 | 文字大小、减少动效、存档/读档、连接信息 | 明确的自动策略/重新开始 | 本地显示偏好 + 后端存档/策略 |

所有页面共用一个全局暂停状态。切去世界页查看排名不会替主角回答。返回生涯时保留阅读位置和当前未提交选择；读档成功后清除属于旧 generation 的临时输入。

## 4. 桌面构图

1440×900 参考：顶部 64px；外边距 32px；主体 CSS Grid `184px minmax(0,1fr) 280px`，列 gap 24px。中心阅读区正文最大约 680px，周围留出适当呼吸空间。不是把这些数值当绝对坐标，窗口变化时由容器重新排布。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ CSC / 职业生涯        第 01 章 · 证明自己       2026.02.01   已同步   │
├───────────┬───────────────────────────────────────┬─────────────────┤
│ 生涯      │ CHAPTER 01 / 赛后 · 训练室             │ 你的近况        │
│ 赛程      │                                       │ 17 岁 / ENTRY   │
│ 战队      │ 训练室的灯还亮着                      │ 当前战队        │
│ 世界      │                                       │ 状态与关系摘要  │
│ 档案      │ 2–4 段当前场景，对话有人物和语境       ├─────────────────┤
│           │ 内容引用真实比赛，不堆属性卡            │ 接下来          │
│ 设置      │                                       │ 下一场正式赛事  │
│           │ ────────────────────────────────────  │ 未兑现承诺      │
│           │ ○ 主动留下复盘                        │                 │
│           │   确定影响/可能后果                    │                 │
│           │ ○ 今晚先独自调整                      │                 │
│           │                                       │                 │
│           │                       [确认这个选择]  │                 │
└───────────┴───────────────────────────────────────┴─────────────────┘
```

首屏只要求当前情境、段落开头、待做事项清晰可见；长场景自然滚动，不为“首屏塞完”缩小字体。中心主 CTA 同时只有一个。右栏最多两个逻辑区，信息多则折叠。不要把右栏塞满饼图、雷达图和今日所有新闻。

世界页改为 HLTV 式紧凑资料布局：中列日期分组新闻，侧列排名/近期比赛；点击一条新闻进入事实详情，不弹出无用 toast。赛事行包含日期、对阵、BO、状态/比分；没有结果显示“未赛”，不能用 0:0 冒充赛果。

## 5. 场景、选择与结果

场景头包含章节、日期、地点、人物。正文不混入 `scene_id`、`option_id`、revision 等实现字段。

以下仅为版式/文风示例，生产必须绑定真实事实与实现效果：

> 训练室的灯还亮着
>
> 其他人已经关了显示器，你的队友却把刚才那一局停在了回合开始的位置。他没有急着评价你的数据，只问了一句：“这里，你当时想让我怎么接？”
>
> 你记得自己先一步走出了掩体。那个决定没法重来，但下一次可以。你把椅子拉近了一点。

只有事实确实包含该回合行为时才可以使用这段具体叙事。数据不足时改成概括性赛后谈话，不凭空断言某人犯错。

选择文案：

- **“把我的思路讲清楚，再一起看一遍。”** — 只有后端实际创建复盘承诺时，才能写“约定在下一场前完成复盘”。
- **“我想先自己整理，明天再谈。”** — 如果实现了延期，再写“这次谈话将延后”；否则不得把没有效果的选项包装成分支。

点选行只改变选中态，点击确认才提交。提交过程中禁用重复确认；失败保留选择并显示具体原因。快捷键 1/2/3 只选中，Enter 在确认按钮有焦点时才提交，输入昵称时不触发快捷键。

结果替换当前场景下半部或进入独立结果视图：首先一句人物/世界反应，然后列出真实即时变化、仍待验证的承诺，最后“继续生涯”。没有实际数值变化也可以显示“约定已记入档案”，但后端必须确实写入。不要每次选择都开一个模态框，不自动跳过结果。

## 6. UI 状态与连接模型

路由管理页面；overlay stack 管理设置、读档确认等覆盖层，只有栈顶接受输入。不要以多个 `isModalOpen/isInScene/isLoading/...` 布尔量组合出矛盾界面。

```text
初次进入：loading → no_game → 创建 → chapter_intro → scene
场景：reading → selected → submitting → outcome → continue
后台推进：advancing → awaiting_choice / checkpoint / season_summary / ending
连接：online → reconnecting → reconciled / failed
```

必要状态：

| 状态 | 呈现与行为 |
|---|---|
| 首次加载 | 与真实布局相近的短骨架；失败后可重试，不无限转圈 |
| 尚未建局 | 昵称、定位与一个创建按钮；故事模式默认 human，后端旧默认 auto 不可遗漏 |
| 没有新闻/报价 | 明确原因和下一步；不填假新闻/假报价 |
| 等待选择 | 推进不可用并解释；玩家仍能查看档案/世界 |
| 提交响应丢失 | 显示“正在确认结果”，按 operation/request ID 对账 |
| 409 过期 | 刷新权威 pending，解释已更新；不得把旧选择自动提交新批次 |
| 断线 | 顶栏提示，保留已读内容；恢复时拉视图/补游标，不凭本地计时推进 |
| 读档失败 | 保留当前游戏与页面，展示可理解原因 |
| 服务端不可达 | 明确错误、重试入口，不静默 fallback 到 demo 数据 |
| 生涯结束 | 结局、关键选择、真实荣誉与重新开始入口；重开不覆盖旧档 |

更新以 WS 事件/失效通知触发查询，断线时可有限退避轮询。禁止每帧读取游戏状态和高频获取 `/state`。业务事实不做乐观更新，显示加载/待确认即可；本地只保存主题、文字大小、阅读位置等显示偏好。

建议前端技术栈：Solid + TypeScript + Vite，沿用项目历史技术方向，但新建最小工程。版本在实施时核对兼容并锁定；不要为了本次设计同时迁移多套框架。CSS 使用 tokens 与局部样式；不引入整套默认后台 UI 主题来决定产品外观。

建议结构（拟新增）：

```text
web/src/
  app/                 router、应用框架、overlay stack
  api/                 Rust DTO 对应类型、REST、WS、错误与重连
  features/career/     SceneReader、ChoiceList、Outcome、ContinueAction
  features/schedule/   赛历、赛事详情、正式比赛回顾
  features/team/       阵容、关系、合同、训练与转会
  features/world/      新闻、排名、世界上下文
  features/archive/    已经历故事、赛季与结局
  features/settings/   偏好、存档与读档
  ui/                  Button、Dialog、DataTable 等小原语
  styles/              tokens、layout、typography
```

不要把所有 API 与所有页面塞进一个全局 store；按 game_id/revision 管理权威查询缓存，UI 草稿另存。不要创建与 Rust 同名但自行计算的 rating/defaultDecision/transferDeadline 函数。

## 7. 响应式、输入与动效

- ≥1200px：三列；768–1199px：主导航收窄/抽屉，辅助栏移至内容后或受控侧面板；<768px：单列，顶部章节与日期，底部 4 个入口“生涯/赛程/世界/更多”，更多收纳战队/档案/设置。
- 手机叙事区左右内边距 20px；选项满宽；底部按钮在正常流或 sticky footer 中，给内容预留真实高度并叠加 `env(safe-area-inset-bottom)`，不得遮住最后一个选项。
- 表格可在明确的数据容器横向滚动，页面本体不能横向溢出；手机赛事列表优先折为两行，保留对阵、时间和结果。
- 1440/1920/768/390 都用 Grid/Flex 的 minmax/min-width:0 布局，不能给整个界面 transform scale 来假装响应式。
- Tab 顺序符合阅读顺序；可见 focus ring；radio/按钮/表格/标题用语义 HTML。弹层 trap focus，Esc 关闭可取消的弹层，关闭后焦点回到触发控件。
- 不把第一个选项默认当作已同意。章节首次进入聚焦标题，随后可导航；全屏对话中背景不可交互。
- 字号可增加到 200% 仍能读与提交；屏幕阅读器只 announce 当前提交状态/新结果，不逐字朗读整条推送流。
- 微交互 120–180ms，场景过渡 250–400ms，只用 opacity/小幅位移；尊重 prefers-reduced-motion。不滚动劫持、不强制逐字打字、不自动播放声音、不每次返回首页重放序章。
- 手柄若纳入实现，映射到与键盘相同的 focus/confirm/back 命令；没有实测设备不能宣称手柄已通过验收。首版硬要求是鼠标、触摸、键盘。

## 8. 视觉与功能验收

先做真实数据的“生涯场景 + 世界列表”两页，确认 tokens、密度与组件后再扩展其余四页。可以用标注为 preview 的 fixture 设计状态，正式路由必须切换到真实 API，不允许 demo/真实数据混用。

截图：`docs/screenshots/career-v1/`，命名含页面、viewport、状态。至少包括新建、章节、待选、结果、赛程、世界、档案、断线、读档恢复；视口包括 1440×900 与 390×844，并抽查 1920×1080、768×1024。

使用实际可用浏览器工具；若 harness 无读图能力，可按 AGENTS §8 使用已有 `scripts/vision-bridge.mjs`，前提是通道/脚本确实可用；不要暴露配置密钥，也不要把访问失败写成 PASS。DOM 核验必须与截图观察结合。

评分（每项 0/1/2 分）：

1. 首屏当前事件和唯一主行动清楚。
2. 中文标题、正文、数据层次一致。
3. 颜色克制且对比度可读。
4. 页面模块按任务重要性排序。
5. 人物/比赛资料真实可追溯。
6. 故事正文不被装饰和指标卡打断。
7. 手机与放大字号无遮挡、溢出。
8. 键盘操作、焦点与弹层返回正确。
9. 加载/冲突/断线/恢复均可理解。
10. 所有可交互入口接到真实功能。

总分至少 17/20；第 5/7/8/10 项不能是 0。**评分只是复核辅助**，必须附截图/实际步骤，不能由生成者一句“高级感达标”代替证据。最终交付注明参考站实时画面若仍未核验，不能称为视觉逐像素对齐。
