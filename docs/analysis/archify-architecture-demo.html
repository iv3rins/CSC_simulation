容量治理（GameManager）

max_active（默认 4）超出 → 把最久未访问的空闲局 gzip 落盘卸载；leased>0 / advancing / saving / restoring 中的局不动。
并发恢复同局由 restoring 标记去重 —— 有专门竞态回归测试 concurrent_restore_of_same_game_never_404s。

统一错误格式：非 2xx 响应体 = { "error": "<人话原因>" }。请求体上限 128MB（长生涯读档）。常规状态码：200/201/202(Human 异步)/400/404/409(批次不匹配·推进中·闸门)/413/422/504(>300s)。

版本契约四件套

  • deny_unknown_fields：未知字段拒绝解析（防静默默认化）
  • 未知版本 > CURRENT_VERSION 拒绝加载
  • 旧档读入经唯一入口 migrate_state() 升到 v9（v5 荣誉积分 ×0.1 量纲归一）
  • 指纹门禁：FNV-1a64(sim_version ‖ canonical) 随 cargo test 默认执行（禁 ignore）

② 结构性限制（设计内妥协，非 bug）

K1 WASM 仅 auto

浏览器内人类交互（EngineStep 状态机）列为 v2。

K2 浮点跨语言

pow/exp 依赖 libm，跨语言 1-2 ulp 差异；概率整数化已消除分支分叉。

K3 无跨版本决策重放

决策点 ID 两次改版，旧档历史日志与新格式重放失配（仅影响展示）。

K4 /state 不可高频拉

20 年 ≈68MB。轮询走 /view + /journal?since= + WS。

K5 请求体 128MB

长生涯读档需要；axum 默认 2MB 会 413。

K6 存档 JSON 起步

体积大但调试友好；postcard 为备选，实测超阈值再评估。
