## 四、前端关键流程

### 1. 游戏启动

```
main.tsx → preloadTeamLogos() → render(<App/>)
App.tsx → GameProvider(boot) → 读 localStorage game_id → attach → 拉 view + journal
```

### 2. 月推进（Human）

```
ControlPage 点推进 → store.advance() → POST /advance
  → WS 收到 { type:"decisions", batch_id, points } → queue.push → DecisionModal 弹出
  → 玩家选择 → submitDecisions(batch_id, decisions) → POST /decisions
  → WS 收到 { type:"step" } → 刷新 view → journal 增量合并
  → month%12==0 → SeasonSummaryModal
```

### 3. FIFA 赛季推进（Auto）

```
ControlPage 点赛季推进 → store.advanceSeason() → POST /advance-season
  → 赛季内 CareerDecisionSource 自动处理（不弹决策）
  → seasonRecap 弹层 → 玩家在办公室主动操作（换队/BP/发言/训练）
```

### 4. LIVE 逐回合

```
live/today 非空（比赛日闸门）→ LivePromptBar 20s 窗口
  → 进入 → POST /live { config } → LiveMatchSession
  → 回合推进：advance → 决策点（economy/util/pace/timeout）→ decide
  → 地图结束 → finish_map → 下一图 / 系列赛结束 → watch 标记
  → 跳过 → POST /live/{id}/skip（结果仍由月末确定性结算）
```

**t2（2026-08）：LIVE 会话由「整页替换」改为「页面内嵌卡片区」**（用户：我的赛程 LIVE
应该是自己在下面一个框里面选择进去观看的，而不是直接占了半屏）。

- `LiveEventView.tsx`：`<Show when={store.liveSession}>` 从页面顶部移到页面**正常内容之后**，
  渲染为独立的 `<section class="live-session-embed">` 卡片区（保留 `LiveMatchSession` 组件与
  props 不变）；赛程进度/参赛队伍/对阵列表/回放列表照常显示在 LIVE 卡片上方；`liveSession`
  为空时不渲染该卡片区。点击对阵列表「进入观战」（`startFixtureLive` → `openLiveSession`）
  后，LIVE 卡片才在下方展开。
- `LiveMatchSession.tsx`：新增可选 prop `embedded?: boolean`（默认 false）——embedded=true
  时头部更紧凑（badge 缩小、比分板 44px→32px、padding 压缩），退出按钮仅 `onClose` 关闭
  会话不清路由；底部 footer 控制按钮保留。
- `styles/live-session.css`：新增 `.live-session--embedded` 紧凑样式；
  `styles/global.css`：新增 `.live-session-embed` 卡片样式（max-width 无强制、border、
  圆角、margin-bottom 12px，不与 .page 全宽冲突）。
- 关闭 LIVE（`onClose`）时仅 `closeLiveSession()` 不清路由（此前是 `closeLiveSession +
  nav(-1)`）；LiveEventView 仍停留在 live 路由上，页面内容不消失。

**t1（2026-08）：LIVE 卡死修复 + 加载性能**：

- `advance()` 不再因 `decision_required=true` 静默跳过：请求体缺失（旧状态/推进响应缺字段/后端拒绝推进）
  时自动 `GET /live` 拉权威视图恢复——`decision_request` 非空直接渲染决策弹窗；仍缺失则提示 +
  保留「重试」按钮；`resumeAttempted` 防无限重拉（恢复仍失败时由用户显式重试）。
- `finished` 以引擎权威值判定（`map_finished || series_finished`）：防止 `map_finished=false` 但引擎已
  `finished` 时 `playing=true` 反复空转（每次推进都补 `setPlaying(false)` + 标记已观看 + 拉复盘）。
- 错误显示保留「重试」入口（按视图状态走恢复决策请求体 / 重新推进 / 重拉视图）；自动播放 timer 在
  error 时停摆；`delayIndex` 为显式依赖——切换推进间隔即重置 timer。
- `LiveEventView.tsx`：`eventAggregate` 由 createSignal+createEffect 改为 `createResource`
  （同 (gameId, event) 缓存，重开页面不重复拉；失败返回 null 语义不变；markFixturesWatched 的
  mutate 写回保留）。
- OverviewPage/CalendarPage/MatchPage 的 calendar 改走 store `getCalendar`（见 11 号文档：缓存 + in-flight 去重）。

**P1（2026-08）：赛事页「进入 LIVE」静默失败修复**（`LiveEventView.tsx` `startFixtureLive`）：

- **根因**：旧实现用轻量 `/view` 投影（`state.world.players`）查双方阵容——该投影只含主角队
  roster（对手不可见），对手槽位恒为 0 → `aSlots/bSlots.length !== 5` 静默 `return`，按钮无任何反馈。
- **修复**：改为 t2 权威口径 `GET /live/today` 的 `team_a_roster/team_b_roster`（含双方首发、排除退役，
  与 store `enterLiveFromPrompt` 一致）；赛事页 fixture 可能是**未开赛**的赛前对阵（今日闸门不含它）→
  按序回退：
  1. `api.liveToday(id).matches` 中按 `(event_name, fixture_id)` 匹配 → 用其 roster；
  2. 匹配不到（未开赛对阵/旧后端缺字段）→ `api.state(id)` 全量查双方 `!p.retired` 首发；
  3. 仍不满 5 人 → **明确 notify 提示**缺员方（我方还差 X 名 / 对手还差 X 名），不再静默返回；
  4. `openLiveSession` config 构建逻辑不变。
- `startFixtureLive` 由同步改为 async；`LiveEventView` 新增解构 `notify`（store 已有）；新增 import
  `LivePlayerSlot / LiveTodayMatch`。不改后端、不新增端点（复用 `api.liveToday`/`api.state`）。

### 5. 断线恢复

```
WS close → status=disconnected → 30s ping 判死 → 重连
  → 全量快照刷新（view）兜底 journal → GET /decisions/pending 拉回遗漏批次
```
