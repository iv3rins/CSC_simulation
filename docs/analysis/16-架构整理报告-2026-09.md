## 二、六大"冗余→错乱"模式（按危害排序）

### 🔴 P0-1【chemistry 三处分裂实现】→ 数据一致性 BUG 温床

**位置**：
- `csc-entities/src/chemistry.rs` — `TeamChemistry`（数据结构 + relation_of/set_relation/adjust）
- `csc-systems/src/chemistry.rs` — `ChemistryEngine`（apply_blunder_reaction/monthly_recovery/cohesion_factor_of/relation_between/point_id_of/reaction_of_option/blunder_point）
- `csc-simulation/src/chemistry_model.rs` — `ChemistryModel`（reaction_of/relation_delta/teammate_morale_delta/self_morale_delta/roll_blunder_kind/cohesion_of/cohesion_factor）

**问题**：
1. `ChemistryEngine::reaction_of_option` 与 `ChemistryModel::reaction_of` 是同一映射；
2. `cohesion_factor_of` 与 `cohesion_factor` 是同一公式；
3. 涉及 world 读写的在 systems，纯函数在 simulation，数据在 entities —— 同一概念被切成 3 个模块。

**典型 BUG 场景**：改"鼓励/指责/无视"的关系增量时，改 `chemistry_model.relation_delta` 忘了同步 `chemistry_engine.apply_blunder_reaction` 内的硬编码，导致前端展示的 delta 与实际生效的 delta 不一致。

**修复方向**：
- 把 `chemistry_model.rs` 的纯函数合并进 `csc-systems/chemistry.rs`（删掉 simulation 层的 chemistry_model）；
- `entities/chemistry.rs` 只留 `TeamChemistry` 结构 + 基础增删改；
- 所有 delta/label 常量集中一张表（ChemistryRule::for_option(option_id) -> (relation_delta, morale_delta, label)）。

## 三、未触发的雷（中等优先级）

### 🟡 P2-1【`csc-app/render.rs` 的 `decision_at` 与 `default_decision` 行为不同】

`decision_at(p, idx)` 用序号选；`default_decision` 用语义。同一文件的同一决策点处理存在**两套不同的选择逻辑**——CLI 空输入 vs CLI 数字输入会走不同分支，可能产生不同世界轨迹。建议合并为：`decision_at(p, 0)` 必须等于 `default_decision(p)`，并加测试锁定。

### 🟡 P2-2【`csc-events/narrator.rs render` 362 行 CC=26】

唯一一个 CC>25 的函数。事件叙事文本生成的 match 巨表。**这不是性能 BUG，是可维护性 BUG**——加新事件类型要在 362 行里找位置。建议拆 `render_<event_kind>` 子函数表驱动。

### 🟡 P2-3【`csc-server/game/mod.rs` 的 `month_end` 与 csc-time 重复】

后端 `csc-server/game/mod.rs:48 fn month_end` 自己解析 "YYYY-MM-DD"，但 `csc-time` crate 已经存在（`csc_time::civil::days_in_month` 已被使用）。建议把这个 helper 上移到 csc-time 或直接用 csc-time 的 API，同时**删除 game/mod.rs 中的本地拷贝**。

### 🟡 P2-4【Jaccard 0.6-0.8 的"软重复"：csc-core/engine.rs、csc-server/routes/mod.rs 内部】

```
csc-core/engine.rs:337    Jaccard=0.67
csc-core/engine.rs:364    Jaccard=0.61
csc-server/routes/mod.rs:1404  Jaccard=0.63
csc-server/routes/mod.rs:1430  Jaccard=0.62
csc-server/routes/mod.rs:1537/1554/1569/1602  多组 0.62-0.69
```

这是 routes 里**8 个 LIVE 相关 handler** 的高度同构——每个都做「取 entry → 锁 snapshot → 调 engine → 序列化 → 错误转换」。建议抽 `with_live_entry(id, match_id, |engine, snap| ...)` 宏/高阶函数，每个 handler 缩到 5 行。

### 🟡 P2-5【`csc-app/main.rs` main 函数嵌套 7 层】

`crates/csc-app/src/main.rs:189` 嵌套 7 层（>5 阈值）。CLI 主循环。建议状态机化或早期返回。
