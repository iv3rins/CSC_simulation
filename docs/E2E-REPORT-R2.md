## 2. 上轮遗留项复核结果

### D1 数据口径差异 → ✅ 谜底揭开（不是转会统计问题）

**三轮数据**（`window.__saveData` 精确统计）：

```
journal MATCH_PLAYED:  414 条（2026-01 ~ 2027-09，每月 17~23 条，均匀分布）
  ├─ 全部 414 条的 winner/loser 都是玩家队（127 Patins 或 35 B8）✅
  ├─ 与源码一致：settlement.rs:164 NPC 对局不写 journal（to_journal=false）
  └─ 疑似重复仅 4 条（1%，BO3 同轮多图可能）
scheduled_records 玩家 fixtures: 180 场（全部 completed）
页面「已完赛」: 160 场（= 荣誉页「160 生涯参赛」，跨页面一致 ✅）
```

**根因**：同一场赛事玩家队实际打 **2~3 轮**（例：Exort Fiesta #0-1，玩家先 11:13 负 Rare Atom、再负 B8——两条都在 journal），journal 每轮都记（414 条）；但 **scheduled_records 每赛事只记 1 个玩家 fixture**（180 场）。即：

> 🔴 **赛程表（scheduled_records）少记了玩家队的多轮对局**（414 vs 180，差 234 场），页面统计基于赛程表所以偏小（160 vs 414 真实场次）。另「已完赛 160」vs 赛程表 180 还有 20 场差的过滤口径待查。

**建议修复**：`scheduled_records` 写入时补全玩家队全部轮次 fixture；或统一三处统计口径（明确"场"=series 还是=轮次）。

### F2 跳过幂等/比赛日死锁 → 🔴 升级为 P0/P1（根因定位到源码行）

本轮实测 + 网络监控 + 源码审查，**缺陷链条完整**：

1. **前端「跳过」按钮从未调用 skip API**：`game.tsx:451` `skipLiveFromPrompt()` 实现是 `await advanceDays(1)`——而 advance 在闸门激活时必返回 409（`routes/mod.rs:1192` 要求先调 `POST /live/today/skip`）。**前后端契约不一致，跳过永远失败**（网络监控证实：点击 N 次，skip API 调用 0 次）。
2. **死锁闭环**：点跳过 → advance 409 → catch 提示"跳过比赛日失败" → 但提示条已先 `setStore("livePrompt", null)` 关闭 → 错误提示被吞 → 闸门永远激活。
3. **「×」关闭承诺落空**：`LivePromptBar.tsx` 宣称"右上角 × 可关闭后手动操作""比赛可在后台正常结算"，实测 × 后推进仍 409——dismiss 仅前端隐藏，后端闸门不认。
4. **玩家被锁死在比赛日**：正常 UI 路径（跳过/×）全部失效，唯一出路是逐场进 LIVE 观战（每天 4 场）或开发者工具调 API。
5. 附：skip API 在无比赛日时调用返回 409"跳过比赛日处理超时"（非幂等空结果，小问题）。

**建议修复**：`skipLiveFromPrompt` 改调 `POST /live/today/skip`；`dismissLivePrompt` 后端同步（或 × 前先 skip）；skip API 幂等化。

### F3 LIVE 决策即时反馈 → 🟠 确认（描述修正）

- 决策提交后**无任何确认反馈**（无 toast、无"已选择抱团补枪"文本、选项组直接消失）——QA 文档"决策后立即有即时反馈文本"未达成。
- 源码修正：`LiveMatchSession.tsx:152` effect 在 `decision_required` 解除后会**自动恢复推进**（上轮判断"不恢复"有误）。
- **回合进度条"不动"的完整机制**（用户问答补充）：自动播放默认开启（0.75/1.50/2.50s 三档）；不动 = ①玩家点了暂停 ②`decision_required` 等决策（此时三个控制按钮全部禁用）③地图结束 ④loading/error；「跳过至赛果」直接算终局不逐格走。

## 3. 新发现

### N1 🔴 布局挤压缺陷（高频、稳定复现）——本轮最重要视觉发现

**触发条件**：比赛日 LIVE 提示条（LivePromptBar）挂载期间（赛事页/赛程页，约 20s 窗口）。

**现象**（截图 `r2-02-event-page.png`、`r2-06-after-exit.png`）：
- 顶栏「CSC 职业之路」与日期被挤压成竖排（每字一行）；
- 左侧 LIVE 信息卡文字完全竖排挤压在极窄列内；
- 主内容区大面积空白，仅剩比赛日提示条。

**对照**：进入 LIVE 观战后（`r2-04-live-in.png`）布局立即恢复正常。上轮旧截图 11-after-enter-live 的 FAIL 即此缺陷，当时误判为"渲染中间态"，本轮确认**稳定复现**——每个比赛日提示条出现的 20s 内页面不可正常浏览。

**建议**：排查 LivePromptBar 挂载时的 CSS 容器宽度（疑似 flex/grid 主轴宽度被提示条挤压塌陷）。

### N2 🟡 Rating 口径轻微不一致

同一时刻三处 Rating：主页 HLTV 数据中心 **1.09** / TOP20 页门槛卡 **1.09** / 个人数据页 **1.10**（179 图"全年来计 K/D/A"）。疑似舍入或统计窗口差异（P3，建议统一口径说明）。

### N3 ✅ 正向确认（本轮表现良好的点）

- **跨页面数据一致**：已完赛 160（赛程页）= 160 生涯参赛（荣誉页）；现金 $242K（主页=办公室页）；队内第 3/5（队伍页）与总评排序一致；VRS 观察"B8 #128→#127"（日志）与顶栏一致。
- **TOP20 加权逻辑生效**：torzsi Rating 1.16 因缺荣誉排第 6（低于 Rating 1.11 的 REZ），评语解释合理——"非主角霸榜"设计达成。
- **决策系统健壮**：13 个批次（每月 1 批）全部正常弹出/提交，`DECISION_MADE` 计数吻合。
- **赛后复盘完整**：回放页含个人复盘（K/D/ADR/KAST）+ HLTV 解读 + 双方记分板（截图 r3-01）。
