## 效果语义

- 关系使用既有双向 adjust；先派生凝聚力，再应用同一选项的显式凝聚力增量，避免覆盖。UI 报告总凝聚力实际变化；上限情况下 +8 不再虚报为 +8。
- 士气/声誉使用 saturating_add + 已有 0..100 边界，报告真实变化；主体失效不静默跳过。
- 承诺的预校验在克隆的轻量 narrative progress 上执行，检查整组 create/fulfill/break 依赖，不复制整个 world；真正提交后才消费 active scene、记录路径和 history。
- StayTeam 记录 committed_to_current_team flag，不再伪写 TeamJoin 记忆；明确合同未变化。
- 旧 schema 的 AcceptTransfer 保留可反序列化，但执行明确报错“签约必须通过真实报价系统”。v2 资产完全移除此效果，改为职业意向 flag；不声称转会或续约发生。

## 内容修订

v2：3 弧、13 场景。第一场赛后不再写第一张图；没有日程事实不写明天比赛；没有角色实体不把队友称为队长或教练；需要关系效果的场景使用 teammate，media/manager 没有关系效果。取消无消费者的旧承诺。压力回访由两条合法前序都创建 trust_conversation，一个月到期；兑现/失信都能结清。转会弧只是意向讨论，退出后一月回访；不虚构两份合同、排名更高的新队、完成签约或首发任命。

## 明确剩余项

1. 正式参赛身份/fixture 事实不够，不能用当前队历史赛果代替；由引擎保守关闭无证据赛后触发。
2. 正式世界/比赛 continuation、后端持久回执与生产 API 三弧闭环不属于此模块完成证据。
3. 静态 schema 验证不能证明动态承诺路径/所有世界条件均可达；正常 driver 的三弧场景覆盖表仍待做。
4. actor 跨整个剧情弧的稳定绑定/角色变动替代分支尚未完整建模；当前只保证 active scene 捕获 actor，失效全拒绝。
5. effects 目前是模块级预校验原子性；写盘失败、整个引擎事务与 receipt 仍需上层统一提交，不在本模块假装已完成。
6. 历史及中文效果展示需要继续通过 TextBundle 统一；immediate 已使用中文承诺标签和通用选择记录，未知 promise 使用“约定”。tracking 保留机器标识，由展示层映射，不裸露在产品正文。
